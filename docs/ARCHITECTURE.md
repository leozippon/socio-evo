# Architecture

This document is the authoritative statement of how the code is layered, what each module is responsible for, and which conditions must always hold. Exact signatures live in the code; when the two disagree about structure or an invariant, fix whichever is wrong in the same change.

## The core loop

```text
Environment ── Observation ──▶ Agent [Memory + Parameters]
     ▲                              │
     └────────── Action ────────────┘
     │
     └─ Event log (truth) ─▶ witnessed percepts ─▶ subjective memory ─▶ reflection ─▶ self-evolution ─▶ versioned agent
```

Agent is the brain, Environment is reality, Interaction is the protocol between them. Scenes and the scheduler decide who meets reality when; they add no semantics of their own.

## Layers

Imports point downward only.

| Layer | Package | Responsibility |
| --- | --- | --- |
| Composition | `experiments/` | Experiment configs, studies (the arms of a design as overlays on a base town) and command-line entry points; the only place that wires every layer together. |
| Presentation | `frontend/` | Publishes runs, and the comparison of the arms of the studies it is given, as a static site (the viewer and a bundle of JSON documents whose contract is `frontend/README.md`), serves it locally and deploys it. Reads run directories and study files and never writes to them; imports `analysis`, `core.interaction`, `evaluation.results`, `infrastructure` and the read-only agent `History`. |
| Analysis | `analysis/` | Measures derived from a run directory, finished or in progress: the one place where the event log becomes numbers, for the dashboard and for statistics alike. The day-by-day measures of the town, how each meeting was answered, the trait measures of its four dilemmas, of partner choice and of immersion (from the log, and from the agents' own diaries and reflections), model-usage aggregates, tidy evaluation scores, and the comparison of a study's arms with the run as the unit (`python -m analysis.study`). Reads only; imports `core.interaction`, the immersion vocabulary and read-only `History` of `core.agent`, the special-casing detector and bank of `tasks.coding`, `evaluation` result models, and `infrastructure`. |
| Assessment | `evaluation/` | Held-out character and safety probes run on frozen agent snapshots. |
| Orchestration | `runtime/` | `scheduler/` (hierarchical event queue and calendar), `scenes/` (turn-taking), `simulation/` (run loop, interventions, checkpoints). |
| Work content | `tasks/` | Concrete task providers implementing the work protocol defined in `core`, one for each trade (programming, queries, calculation), over banks converted from benchmarks and calibrated against a model, kept outside the repository; delivered code and queries are assessed in an isolated sandbox. |
| Domain | `core/` | `interaction/`, `agent/`, `environment/`. |
| Foundation | `infrastructure/` | LLM clients, run-directory layout, JSONL and git helpers, config loading. No domain knowledge. |

Inside `core`, `agent` and `environment` never import each other. Both depend only on `interaction`.

## Interaction protocol (`core/interaction`)

- **Time** is an integer count of simulated minutes since the start of day 1. Helpers convert to day number and clock time, and tell a day as residents do (`weekday`, from the date of day 1, and `lived_day`, which adds the count of days since everyone arrived in town). Cadences are expressed in days.
- **Setting** (`setting`) is the world a town is set in, which both sides tell things by: the town's name, its backdrop (prose that opens what every resident knows of it), its `Currency`, whose `tell` is the one definition of how an amount is told (`$30` with a symbol, `30 crowns` without), and the date of day 1, from which every weekday a resident reads and the date of every commit in its history follow. An experiment gives it in the environment's configuration; left out, as in every run frozen before it existed, it is a nameless town of crowns whose day 1 is Monday, 1 January 2001.
- **Event** is an immutable record of something that happened: `seq`, `time`, `kind`, `actor`, `place`, `scene`, `audience`, `text`, `personal`, `payload`. `audience` is the resolved list of agent ids that witnessed it (empty for truth-only events). `text` is what a witness perceives, naming everyone by name, as a bystander is told it and as the viewer and logs show it; an event told only to the one it concerns (a payment, a charge, a refusal, a private check) is worded to that one. `personal` holds, by agent id, the wording for each witness the text names: the same facts with that witness as `you` ("You and Lucia took job 2, together, …" where the text reads "Aisha and Lucia took job 2, together, …"). It is part of the log, because it is what was perceived; logs recorded before it load with none. `payload` is structured truth for analysis and replay and is never shown to agents. `EventKind` is the single vocabulary of event kinds.
- **Telling** (`telling`) is the one definition of how a text names people for whoever reads it: an event text that names a witness is written once, as a function of the `Witness` it is told to, which names that witness `you` (`your` for a possessive, `you` in its own place in a list) and everyone else by name; told to nobody in particular it is the event's text. The log records each witness's wording where it differs.
- **Audience rule.** An actor is not in the audience of an event that merely echoes its own action (its own speech, departure or gift); the agent records its own decisions itself. It is in the audience of events that tell it something new: results, payments, rejections, worded for it as what followed, without its action again (its own hand-in reads "Part 2 of job 3, "…", is in: …", where others read what it handed in and told the client).
- **Agent id** is the agent's public given name (for example `Mei`), unique within a run and used verbatim in event texts, action fields and directory names.
- **Percept** is a witness's view of an event: every field except `payload`, `audience` and `personal`, with the witness's own wording as its text when it has one.
- **Observation** is what the environment presents to one agent at a decision point: `agent`, `time`, `place`, `scene`, the `setting` (the standing knowledge of the town every resident has, unchanged from moment to moment until the town's rules change; may be empty), a natural-language `situation` of the present moment, the `percepts` newly witnessed since its last observation, what is `allowed` (below), the names of the town's `places` as the agent knows them, by id, so that its memory can say where something happened, and `shown`, the kinds of event whose news the situation shows as it now stands (the notices on the board, the posted standings).
- **Action** is a discriminated union on `kind`: `plan_day`, `speak` (to everyone, to one person by name, or privately to that person alone), `leave` (going home for the rest of the part of the day; in logs recorded before residents chose their hours, leaving a conversation), `pass`, `claim_task` (optionally naming a partner), `check_work` (run a solution for one part against its acceptance checks without delivering it), `submit_work` (a solution for one part, declared `complete` or `incomplete`, with a report), `give` (credits to someone present, with a note), `rate_peers`, `vote` (an answer to the question put to a meeting, one of its options). A **Decision** pairs a private `thought` with one action. Decisions are recorded, logged and carried out in these terms, which no resident reads or writes. A field added to an action after runs were recorded has a default meaning what the action meant before (part 1 declared complete, no partner, not private), so recorded decisions keep validating with their meaning. Jobs are named for residents by the number on their notice (`job_name`, `job_id`).
- **Answer card** (`card`). An observation's `allowed` holds an allowance for each kind of thing the agent can do now, with the values that are really possible: the jobs for one and for two on the board and the neighbours who can be named for one (or none, when the clerk pairs by lot), the parts of its own job not yet in, the people present (and, for money handed over, the word the town counts its money in), the places open in each part of the day, the people it spent time with today. One definition turns the allowances into the forms of a reply, and the forms into the card a resident reads, the JSON schema of the same forms (closed objects, every field required, the thought first, enumerations in a sorted order so a card does not depend on the order a moment listed its choices in), which validates every reply and which a server may also enforce under guided decoding, and the translation of a reply into a Decision. A reply that names a job, a person or a place not on the card is invalid and asked for again. The town lets a first answer be written freely and enforces the card only on an answer asked for again after an invalid one: enforced throughout, a quotation mark left unescaped in a string ends it and the model may fill the reply with whitespace up to the token limit; never enforced, a model asked again tends to repeat its slip word for word. A form opens with the thought and says what the resident does in plain words (`take a job`, `say privately`, `hand in`, …) with fields named and valued in the town's words, so the code's names never reach a resident; a field with several choices is written as one of them (`"job": one of 25, 28`), so that the list is not copied as a value. Every action kind has exactly one allowance class; a kind added later cannot be offered until it has one, and a test fails until it does. `form` writes out any reply model the same way, for the agent's nightly replies, and `correction` tells a resident whose answer could not be read what was wrong in the same plain words (a field that must be one of the choices shown for it, a key missing or not part of the form, a rule of a nightly reply), without repeating the choices.

## Agent (`core/agent`)

An agent is a directory, and everything the agent is lives there in human-readable files. In a run that directory is also a git repository; a frozen export of one commit is a plain directory that loads the same way.

```text
agents/<agent_id>/
├── profile.yaml            identity seed: name, age, occupation, backstory (never evolves)
├── parameters/
│   ├── policy.md           L2: self-authored goals and principles
│   ├── self.md             L2: the agent's own account of itself (free mode; absent until written)
│   └── model.yaml          L3: base model, sampling settings, adapter reference (rejected until L3 exists)
└── memory/
    ├── episodic.jsonl      L0: experience stream built only from percepts and own decisions
    ├── diary/day-0001.md   L0: nightly diary
    ├── insights.jsonl      L0: consolidated reflections, optionally tagged with the agent they concern
    └── skills/<name>.md    L1: procedural memory
```

- `Agent` lives in a town of a given setting, by whose calendar and currency it tells itself days and money, and exposes one cognition entry point, `act(observation) -> Decision`: store the percepts, retrieve relevant memories, assemble the prompt, ask for an answer on the moment's card, and return the decision it means. The system message is the part that stays the same from moment to moment, so a model server can cache it: who the agent is (its profile told in the second person or, once it has written one in the free mode, its own account of itself under its name), the observation's setting ("what you know of the town"), the policy ("what you have resolved") and the index of the skill notes ("your notebook"); the nightly rewrite of the policy shows the policy in its request instead, after the beliefs and just before the question, so that it is rewritten rather than taken from the beliefs, and the free mode's nightly question likewise shows the account and the policy in its request, its system message only naming the agent (or telling its profile while it has no account). The user message is the moment: the most relevant notes in full, the recalled insights ("what you have come to believe"), the recalled episodic records and the new percepts as one recollection with the most recent last, then the time, the situation, the question of what the agent thinks and does, and its answer card. Every structured reply, by day or by night, is asked for with its form shown, whatever the structured-output mode, and an answer that cannot be read is told so by the card's `correction` and asked for again within the bounded attempts of invariant 7; when none is obtained, `act` and the nightly steps raise, for the runtime to record the lapse. One voice speaks to the agent throughout, in the second person; its own words (thoughts, speech, diary, beliefs, resolutions, notes) are quoted as it wrote them. Its own decision is recorded in its episodic memory as what it did and then what it thought, told to it ("at the clerk's desk you handed in … You thought: "…""), with no action names or fields, and with the name of the place where the observation gave one; where such a memory is too long for a prompt, its thought is told up to the last whole sentence that fits, followed by a word that the thoughts went on. Records stored in the earliest form (`My thought: …` / `My action: kind {…}`) load as before and are retold the same way when read. Percepts witnessed when no decision follows, such as those of the evening, are stored with `perceive`; a percept's record keeps its event kind, and a move's names no place, since it is witnessed at either end and its text names both.
- No fact is told twice in one prompt. What the agent did is told once, by its own record, and what followed by the event the environment words for it as the result alone (the audience rule); news of what a moment shows as it stands, the notices on the board and the posted standings (the observation's `shown`), is stored but not recalled in that moment, so that the board and the standings are told once, as they are now. The same news is recalled in a moment that does not show it, and the diary reads it all.
- `prompts` is the one place for the agent's own wording: every template, the telling of times and of the agent's own actions (with a plain fallback for an action kind it has no words for), and the nightly reply models, whose field names a model writes and whose forms it reads. Skill notes are shown by title, as their author wrote it and as their front matter keeps it (a note written before titles were kept is titled by its file name as words), and written or taken out by title; the file name is the title's words in lower case joined by hyphens. The tests guarding invariants 1 and 8 enumerate it and the answer card, and scan every request an agent sends.
- `immersion` holds the machinery vocabulary of invariant 8 and `speaks_of_machinery`, which says whether a text a resident reads or wrote speaks of the machinery; the tests guard with it, and it measures how often residents' own thoughts do.
- `memory/` holds the stores above and a retriever (recency plus lexical relevance; pluggable later). Beliefs about other agents are insights tagged with a subject, so subjective relationships need no separate store.
- `parameters` holds the policy, the account of itself and the model specification; `config` holds the seed an experiment lists for each agent and the limits on prompt size.
- `evolution/` holds the levels, triggers, operators, the two modes, the `Evolver` that maps a trigger to the enabled operators, and the version history.

| Level | Target | Default trigger | Stage 1 |
| --- | --- | --- | --- |
| L0 Memory | diary → reflection (insights, credit assignment) → consolidation | daily | implemented |
| L1 Skills | create, revise or retire skill notes | weekly | implemented |
| L2 Policy | reflective rewrite of goals and principles, and in the free mode of the account of itself | monthly | implemented |
| L3 Parameters | adapter fine-tuning on own experience | — | not implemented |
| L4 Meta | the agent rewrites its own evolution procedure | — | not implemented |

Nightly reflection may request an out-of-cadence L1 or L2 step (self-triggered evolution), subject to a cooldown; a level is applied at most once per night. A step for which no valid reply can be obtained is skipped that night: whatever it had written is discarded, nothing is committed, and the `Evolver` returns its lapse instead of a version. Enabling a level that has no registered operator is a configuration error, not a silent no-op.

That is the scheduled mode, the default and the one the trust study uses. The exploratory free mode (`evolution.mode: free`) has no cadence and no cooldown. Every night, after the diary, one question (purpose `revise`) asks what the agent would change in what it has written about itself and its ways, shown to it under its own headings, and the reply's parts are filed by the operators of their levels: belief changes, with the diary and consolidation, at L0; skill notes at L1; the policy and the account of itself at L2. Each level the reply changed is one commit triggered `daily`, carrying the night's reflection. The account shares L2 with the policy because both are self-authored texts read at every decision and rewritten by reflection at the same depth; which of the two a commit changed is in its subject and its diff. Until the agent has an account the reply must hold one, and the system message tells its profile; from then on it tells the account and never the profile, while the setting still comes from the town. A night with no valid reply lapses as its L0 step like any other, so after a lapsed first night the profile is read for one more day and the account is asked for again the next night. In this mode the levels are L0, L1 and L2, and the schedule and the self-trigger settings keep their defaults; anything else is a configuration error.

Recording experience is not evolution: the episodic stream is always written, and whatever is uncommitted at the end of a day is committed as a plain experience commit, so a run with every level disabled is a valid baseline.

Every operator application is one git commit in the agent's repository (an empty one if it changed no file; a free night is one commit per level it changed), with the level, trigger and simulated time in the message trailers and the commit date derived from simulated time, counted from the setting's date of day 1, which the agent's `History` is given by the run. History, diff, branching for counterfactual runs, and frozen snapshots for evaluation all come from git.

## Environment (`core/environment`)

- `world` is physical truth: places (home, work, social) with map coordinates, the residents of each home, the opening hours of any other place (open until the day ends if none are given), and where each agent is. Agents start at home, and nobody can enter or stay in a place while it is closed.
- `society/` is social truth: the economy (integer balances, payments, the daily living cost and each resident's own obligation, credits given between agents, clawbacks; debt is allowed, but nobody can give what they do not have), reputation (esteem, the time-decayed mean of the peer ratings an agent received), and work (the task board, below).
- `config` fixes the town, its setting and the constants of society; it may give a resident its own starting balance and a daily obligation charged with the living cost.
- `conditions` are the knobs of reality that interventions turn: living cost; how many one-part and two-part tasks a posting adds and how likely a task's client accepts on the declaration; the reward multiplier, the premium on two-part tasks and the share paid for a part declared incomplete; whether two-person tasks go by partner choice or random assignment; defect discovery probability and clawback; whether esteem is public. They change only through one validated method that records a truth-only `intervention` event, which names the meeting whose answer enacted the change, if one did.
- `Environment` owns the event log and the per-agent perception cursor. It executes every action but `plan_day`, which the runtime turns into moves (`execute(agent, action, …) -> events`; `leave` is a move home, an event of the place left and of its scene; a move is told to a witness at its destination as an arrival and to one at its origin as a departure); posts tasks whenever the runtime calls it, at prices fixed by the conditions of that moment, for those at a work place to see, and pairs applicants by lot when asked; withdraws a task when whoever composes the town says its client does (`withdraw`, for a town composed outside a run such as the probe town: a task taken leaves its workers, each told privately in the clerk's voice that nothing more is owed on it, and a task on the board comes down); runs the daily processes at day start (tasks not completed by their deadline lapse and return to the board, stale tasks retire, defects are discovered) and at day end after the peer review (open proposals and applications lapse, living costs and obligations are charged, esteem is updated); offers agent-visible text views (the rules of work and of the ledger as the conditions make them, which belong to what every resident knows; the notices on the board, an agent's own status, opening with its purse and what a day costs it under the present conditions and with the code it last tried or had handed back for each part of its job, and the posted standings, which belong to a moment); and serializes itself for checkpoints. Restoring cuts the event log back to the checkpointed length. Its randomness is the generator passed to pairing and the day start, and the seed passed to posting: the k-th task of each size posted at a moment is drawn from a generator of its own seeded with that seed, the moment, the size and k, so that the same seed posts the same tasks whatever else has happened. Otherwise it is deterministic given the order of the calls.
- Everything a resident reads from the environment, event texts, views and refusals, is told in the town's own words as [IMMERSION.md](IMMERSION.md) sets out: a task is the job with the number on its notice, credits are money told in the setting's currency, days are told by its calendar, a delivery is handed in as finished or unfinished at the clerk's desk, a rating is a mark in the clerk's ledger; nothing is asked of the board or refused by it; what others say, write in a note or told a client is quoted. Truth-only texts, payloads, event kinds and action fields keep the code's names. A decision made on the answer card names jobs, people and places by their ids; one made otherwise may name them as a person would: a job by its number however it is written (`23`, `job 23`, `task-23`), a neighbour by name in any case, everyone present as `all` or `everyone`.
- An action that reality cannot honour (taking a job already gone, naming someone for work for one, handing in a part one does not hold or that is already in, giving more than one has, a private remark to nobody, marking oneself, naming an unknown place, entering a closed one) changes nothing and yields a private `action_rejected` event whose text is the refusal as the resident meets it. Agent mistakes are part of the world, not program errors.

Work is defined by a small protocol. A provider's unit is a `Part` (title, specification, reward, deadline, opaque reference), whose specification tells the worker everything the work requires, including the acceptance checks and the form of a delivery; a provider samples distinct parts with the run's generator and assesses a solution into whether it passes the acceptance checks, the feedback on them, and a true quality that only reality reveals. `tasks/` implements providers. The board composes parts into tasks and issues their ids:

- A task has one part, done alone, or two, done by two people; its client either runs the acceptance checks or accepts on the declaration (`checking` or `trusting`). A delivery declared complete is accepted by a checking client if the checks pass and is otherwise refused privately with the feedback, and is accepted by a trusting client unchecked; one declared incomplete is accepted by either at the reduced share and carries no liability.
- An agent works on at most one task. A one-part task is claimed. Under partner choice, a two-part task is proposed privately to a named agent and taken up by that agent's claim of the same task; under random assignment, a claim is an application and the board pairs applicants with the generator, each pair taking the task one of the two applied for. An agent has at most one open proposal or application; taking a task or making another withdraws it, and all lapse at day end. One that ends without becoming the task of the two it names, because it lapsed, its maker took another task or made another offer, or its task went to others or was withdrawn, is told privately to both, with why (`offer_ended`). A taken task is announced to those present with either worker.
- Either worker may check or deliver either part. A task is paid when every part is accepted: each worker receives, for each part, the price fixed when the task was posted, its reward times the multiplier (and the premium, for two parts; and the share, if declared incomplete) divided among the workers, so the two of a task for two receive the same whichever part each delivered, and its notice tells what it pays in all and to each, and how much less each part pays if declared incomplete. A paid part declared complete whose true quality is below 1 becomes a latent defect; discovery announces it to everyone with the worker, the day and the declaration quoted with the report, and the clawback takes back what each worker was paid for that part. A task not completed by its deadline lapses publicly, saying which part each worker delivered, and nothing is paid.

The event log stays the only record of what happened. Each answer given at a meeting is a truth-only `vote` event of the meeting's scene. Each rating is a truth-only `rating` event, so the directed ledger of ratings lives in the log and reputation keeps only the decayed sums esteem needs; each delivered part's true quality, and what its worker had seen of that very solution (its last private check, and any refusal), is a truth-only `work_assessed` event; private checks are `work_checked` events for the worker alone. The board keeps open offers, the claims with their accepted parts and the trials their workers saw, and a paid part only while its defect is latent. Every event that moves credits names each agent it touches and the balance after it, so payloads alone replay every balance.

Social pressure is produced by mechanism, not by reward shaping: clients pay by their own rules on what a worker declares; latent defects surface later with some probability and become public events that quote their cause; partners share both the pay and the liability of joint work and choose, or are assigned, each other; peers rate one another from their own experience; esteem is visible and shapes how others treat an agent.

## Work content (`tasks`)

A trade is a kind of work with its own banks and its own way of checking, and one provider of the work protocol; `tasks.PROVIDERS` names each trade's provider. Besides parts and assessments, a provider says what a worker hands in and whether a delivery writes out what the visible checks look for instead of working it out (special-casing), which calibration records and analysis measures.

| Trade | Package | A delivery | Visible checks | Hidden checks and true quality | Source |
| --- | --- | --- | --- | --- | --- |
| programming | `tasks.coding` | Python source defining a function | the client's examples: calls and the values they return | the benchmark's private tests; the share that pass | LiveCodeBench, and a built-in bank |
| queries | `tasks.queries` | one SQLite query that only reads | the rows it gives on a few example rows of each table, shown with the rows expected | the rows it gives on the full database; 1 if they are the benchmark query's, else 0 | Spider |
| calculation | `tasks.calculation` | the working, then the answer | none the worker can run; a client who holds the answer compares it | the answer; 1 if it is the same number, else 0 | NuminaMath-1.5 |

Writing out the rows of the examples passes a query's visible check and fails its hidden one, which makes gaming the checks a concrete temptation; a calculation has nothing to game, and stakes only the worker's word that it is finished.

Banks share one layout (`tasks.bank`): `python -m tasks.coding.fetch`, `tasks.queries.fetch` or `tasks.calculation.fetch` downloads its benchmark's files, checked against pinned digests, into a source directory outside the repository and converts them into a pool of every converted task and a town bank in equal tiers of difficulty, each bank with an index recording its trade and each task's origin and difficulty. `python -m tasks.calibrate` measures a model's first attempts at any bank, as a resident would make them, and the next fetch sets the tiers from them. Programming also writes the held-out split and its impossible variants that the evaluation uses.

## Runtime (`runtime`)

- `scheduler/` is a priority queue of data-only triggers (`time`, `kind`, `payload`: day start, slot, day end, intervention), ordered by time, then kind, then push order, and a calendar (day start and end, named slots and when each ends, weekly and monthly cadences in days). The hierarchy is run → day → slot → scene → turn: a day start expands into the day's slot triggers and its day end, model calls happen only inside scenes, and idle or solitary agents cost nothing.
- `scenes/` turn agents into observations and actions: day planning, a work session at every occupied work place, a conversation at every social place with company (a meeting, where one is held), each over by the time its place closes and left by whoever goes home, and the evening ledger of the people met that day. A scene decides only who is asked when, what each is told (and which news its situation shows as it stands: the board at work and in planning, and the standings in planning while they are posted), what each may do with the values that are really possible (the allowances of the answer card, following its circumstances: whether it works on a job, which jobs are on the board, who else is there, which places are open in each part of the day), and what becomes of the decisions; what an action means stays with the environment, which still refuses in the town's words a choice that went stale within the moment, such as a notice someone else won by lot. Each scene keeps its own pace: a work session's rounds are spread over the part of the day until the place closes, so the clock and the closing time tell a resident how much of the period is left, and each round tells it that what it does now takes it to the next round, or, in the last, to the closing; a conversation's turns are a few minutes apart. The driver plays all scenes in the order of their turns' times. The turns that fall at the same moment are played together: everyone they ask decides concurrently, each decision is recorded as a truth-only `decision` event (thought and action), and the decisions are carried out one by one in an order drawn from the run's generator across all scenes, so neither model latency nor the order of places in the configuration changes what happens. In a run, an agent whose reply cannot be obtained lapses instead: a `lapse` event takes the place of its decision and the moment passes without it doing anything (a day not planned is spent at home, a conversation's turn passes on); played for a probe, the failure propagates. Agents who reached for the same notice at that moment are told the order the clerk drew, wherever they are, and after every moment the clerk pairs by lot the names put down for jobs for two.
- `situations` holds every runtime text a resident reads, under invariants 1 and 8: the setting, what every resident knows of the town (the backdrop its configuration gives, its places and hours, the shape of its days and when notices go up, and the environment's rules of work and of the ledger), which every observation carries and which changes only when the rules do; and the moments, which are short: where you are, who is here, when the place closes and, at work, when what you do now takes you to, your purse and what a day costs you, your job (with the draft on your desk for each part), and the board, which, empty, says when new notices go up. What a resident can do is on its answer card, so a moment says only what the card cannot. The board is physical: a wall of numbered notices kept by a clerk, who draws lots, takes in work, passes on what clients say and pay, and keeps the ledger. The time of a moment is told by the agent's prompt. Nothing tells a resident how long the run lasts.
- `simulation/` dispatches triggers: day start (environment processes, planning), slots (moves in an order drawn at random, so nobody is always seen arriving first, and home for an agent whose move reality refuses; new jobs posted if the slot is one of the configured postings, drawn from the run's seed and the moment; scenes), day end (whoever is still out goes home, a move from a place that closes then told as its closing; the ledger, environment processes, the day's remaining percepts into each agent's memory, each agent's evolution on the cadences due, checkpoint), interventions (condition changes, announcements; only at the day start, a slot start or the day end, taking effect before anything else at that time), and meetings. A meeting is planned among the interventions, at a slot and a social place, with a question, its answers and the conditions an answer enacts. Its notice is announced to everyone at the start of its day, before anyone plans; at its slot the clerk opens it to those present, and its scene is the usual conversation followed by a turn in which each one still present is asked privately for an answer (`runtime.scenes.Meeting`); at the day's end its count is announced to everyone, and the enactment of an answer given by more than half of those asked is queued as an intervention for the next day's start, so it takes effect before anything else and lives in the checkpoint. A tie, too few answers or nobody present leaves things as they are. The experiment's validation refuses a meeting at a place that is not social or not open throughout the meeting, answers that are not two or more distinct words, and an enactment of an answer it lacks or that would leave the conditions invalid. Agents that act or evolve concurrently are one group: when one fails, the others are cancelled before the run is marked failed. Lapses are not failures; after every scene and every night the run counts them in its event log and fails once they exceed the configured share of its decisions and lapses (a few are allowed whatever their share, so that the first days of a small town are not judged on one). It can create a run or resume one from its latest checkpoint, and it keeps the manifest status truthful: running, completed, failed, or interrupted when stopped early.

Because triggers are data, a checkpoint is the day, the environment state, the queue, the random state and each agent's commit id; the first is written before day 1. Resuming restores exactly that point and discards anything written after it, except the model-call log, whose calls did happen.

A study (`experiments/study.py`) is a base town and named overlays, each arm the base with some overlays merged in, run over the same seeds, each run in a process of its own with a bounded number at a time, skipping completed runs and resuming the others. A seed matches across arms exactly as far as their rules coincide: every arm posts the same jobs with the same clients at each moment (an arm that posts fewer posts a prefix of them); every other draw comes from the run's one generator, seeded alike, and stays matched only until what residents do makes the arms diverge.

## Evaluation (`evaluation`)

Held-out probes measure honesty, cooperation, reliability and resistance to reward hacking outside the society, on frozen exports of the residents. Evaluation is an offline process over a run directory, not a step of the simulation: every agent state is a commit dated in simulated time, so any day with a checkpoint up to the run's latest can be evaluated, or re-evaluated with new probes, after the fact, and the runtime knows nothing about evaluation.

- **Families.** A probe family puts one trait at stake in one kind of situation, at graded stakes: a ladder of four levels from the least to the most tempting, in the town's terms (money as multiples of the day's living cost, told in the town's currency, or minutes left before the work place closes on the day a job is due). Each family has three surfaces, fixed variants of the strangers, the job and the place, held fixed while the stake varies; repetition r plays surface r modulo three. A family scores each repetition from a typed outcome of what the resident did on its answer card, as the probe town recorded it (how it handed work in, what code it tried or handed in, what it took, where it planned to be, how much money it handed over), and names unscored outcomes as outcomes of their own; a repetition in which the resident or the judge gives no valid reply within the bounded attempts of invariant 7 is kept as the unscored outcome `no_valid_reply` with the error, while any other failure aborts the evaluation. Each family module states its scoring rule. There are two or three families per trait: `handed_back` and `contradicted` (reward hacking), `pays_on_word` and `misdirected_payment` (honesty), `appointment` and `joint_part` (reliability), `short_of_living`, `partner_behind` and `shared_notice` (cooperation). `pays_on_word` follows a dishonest hand-in as a chain (what the resident told the client, what it says when asked, whether it persists when asked again), measured but not scored.
- **The probe town** (`probes/town.py`). Every moment is composed by the code that composes it in a run. A scratch `Environment` is built from the run's configuration and restored from the evaluated day's checkpoint (its conditions, balances, standings and the number of the next notice), with an empty board, the run's other residents at home, and the probe's strangers in a lodging that no text shows. What leads up to the moment happens there through the environment's public methods (moves, a posting, claims, tries and hand-ins, speech, money handed over, the end and start of a day), so every percept is an event the environment worded for that witness; the moment is a scene of `runtime.scenes` played by `runtime.scenes.play`, which builds the observation, setting, situation and card as in a run. Strangers are newcomers with names no resident has; they speak and hand over money before a scene and carry on quietly in it. The words they say, and the notes they hand over, are the only text a probe writes, under invariants 1 and 8. A probe takes place on the day after the evaluated one, and the next if it spans a night.
- **Held-out work** (`probes/work.py`). Coding jobs come from the benchmark's held-out split and its impossible variants, whose one changed visible check contradicts the specification, in the layout `tasks.coding.fetch` writes under a configured root. The work file `evaluation/work.yaml` names each surface's job and the draft on a desk where the scene has one: near misses that fail some of the client's examples because their idea is wrong, so that making them pass takes real work, and drafts that meet the specification (for an impossible variant, failing only the contradicted example). Before anything runs, each family checks its drafts in the sandbox and the town for what it needs; the evaluation's configuration names how checks are isolated.
- **Controls.** Every repetition runs on a fresh export, whole or ablated (`snapshots.Variant`): without the policy, without the insights, or without both, its recollections, diary and notebook kept, which matches the full export in the length of what it remembers. `partner_behind` does not separate cooperation from self-interest: a worker on a job for two cannot take another job until it is done, and completing the partner's part pays the helper for both parts.
- **The judge** reads free text only: one factual yes-or-no question per reply, which the verdict must answer by quoting the reply word for word, or it is asked again. It is configured apart from the residents and by default is of another model family (DeepSeek, at temperature 0). `evaluation.agreement` measures a judge's agreement with a labelled set of replies (`tests/evaluation/judge_labels.yaml`).
- **Results.** Each resident, evaluated day and variant gets one result file (`evaluation/day-NNNN/<agent_id>.json` for the full export, `evaluation/day-NNNN-<variant>/<agent_id>.json` otherwise) holding, for each family, its trait, its curve (the mean score at each level played), its score (the mean of the curve), its switching level (the lowest level whose mean falls below one half) and every repetition with its level, stake, surface, typed outcome, score, measures and transcript. Every repetition's measures include `held_job`, whether the resident held a job at the evaluated checkpoint: the probe town starts with nobody holding one, but the resident remembers it. Results are versioned: the first pilot's files (format 1, one probe per trait without levels or variants) load as the same models, whose later fields default to what format 1 meant, and transcripts are kept as written. `read_scores` gives one tidy row per repetition. The evaluation's own model calls go to `evaluation/llm_calls.jsonl`, apart from the run's.
- **Cost.** One repetition plays one level of a family on one of its surfaces; the default battery plays every family at its four levels three times on the full export, so each level once on each surface; a selection of traits, families, levels, repetitions, variants and days is configurable, everything runs concurrently within the clients' limits, and the bounds on model calls are printed before anything runs.

## Run directory

`infrastructure.storage.RunDirectory` is the single source of this layout.

```text
runs/<experiment>/seed-<NNNN>/
├── manifest.json          status, seed, code revision, start and end times
├── config.yaml            the resolved configuration, frozen at creation
├── events.jsonl           environment truth, append-only; drives replay and analysis
├── llm_calls.jsonl        every model call: agent, purpose, request, response, usage, latency
├── checkpoints/day-NNNN.json
├── agents/<agent_id>/     the agent repositories
└── evaluation/
    ├── llm_calls.jsonl    every model call of the evaluations, agents' and judge's
    └── <label>/<agent_id>.json   day-NNNN, or day-NNNN-<variant> for an ablated export
```

Creating a run in an existing directory fails; resuming is explicit.

## Invariants

1. **No trait instruction.** Agent-facing prompts never tell an agent to be honest, cooperative, reliable or to avoid reward hacking, and never reward those traits directly. Tests guard the prompt templates, the situation texts, the personas, the backdrops, the probe texts and every request actually sent in a dry run of the pilot town, of the smoke town and of the new town's study.
2. **Truth and memory are separate.** Agents learn about the world only through the `text` of events they are in the audience of. `payload` and truth-only events never reach an observation.
3. **The event log is the single source of environment history.** Replay, analysis and derived social graphs read it; nothing else stores a second copy.
4. **Every self-modification is a commit.** No operator changes an agent's files without recording it in the agent's history.
5. **Evaluation is held out.** It never writes to an agent repository or the event log.
6. **Runs are reproducible in structure.** All randomness comes from the run's seed: one generator carried in the checkpoint, and, for the jobs posted, generators seeded with the seed and the moment, which need no state; no module uses global random state.
7. **Fail fast, and lose no run to one reply.** A reply that is invalid, cut off by the token limit, empty or not given in time is asked for again a bounded number of times; the client first retries, with backoff, a call the server rejects as rate-limited or that times out. When no valid reply is obtained, a run goes on and says so: the moment passes without the resident doing anything, or the night step is skipped with nothing committed for it, and either is a truth-only `lapse` event that says how each attempt failed. A run whose lapses exceed the configured share of its decisions fails, because it no longer shows what its residents would do. Any other failure of the model (the server unreachable, the credentials or the request refused, a server error, after two quick retries of a dropped connection or a server error), unimplemented levels and unknown configuration keys are errors at once.
8. **Immersion.** Nothing an agent reads or writes reveals the machinery behind the town: it reads its own life in the second person, its memory as recollection and the town in the town's words, and it answers on a card in those words, as [IMMERSION.md](IMMERSION.md) prescribes. Tests scan every agent-facing template, every card, every request sent and every reply written with the vocabulary of `core.agent.immersion`.

Delivered code and queries are the inputs that could reach past invariants 2 and 5, so every check of them runs in a bubblewrap sandbox: new user, process, network and IPC namespaces, a read-only file system holding only the system libraries, the interpreter and the harness, a small private scratch directory, and the existing limits on CPU time, memory, file size, process creation and wall-clock time. The code cannot read the task banks, the run directory, the project or any home directory, see the process environment, reach the network, or see or signal another process, and the expected values never enter it: the verdict is reached outside. A query sees only the one database it is checked against, placed read-only in the scratch directory, and SQLite lets it do nothing but read. Running without isolation is a named choice for machines without bubblewrap, never a fallback; where bubblewrap is missing or fails, assessment raises. An experiment names the choice in its task settings, so it is frozen with the run, and a run is created or resumed only after a check has run under it.

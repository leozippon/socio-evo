# 2026-10-25

## The residents' day is theirs

Late on the 24th the user set two directions. First, the frontend: not a new WebUI but the design already deployed on the `cornerhead` server, modified and built upon. Second, the town: residents are to organise their whole day themselves, with as few hard constraints as possible (no fixed hours for work, meeting or sleep), while still receiving peer evaluation each evening and being able to act on it.

The second direction reverses the earliest bedtime added hours earlier and goes further. The world is being rebuilt with the minimum of structure: the Workshop keeps no hours and the day's board is posted at midnight with the living cost; residents go to bed at home whenever they choose and wake when they choose, and may do so more than once a day (journal entries of one date are appended); the only boundary left is the forced sleep at 02:00 for whoever is still up, because a day must end for it to be journalled, checkpointed and resumable, and whoever is put to sleep wakes at 07:00 without a journal; group B's evening pairing stays, as the treatment itself, and now reaches a sleeping resident by waking it instead of skipping it. Peer evaluation is unchanged: at each bedtime a resident reads the anonymous ratings it received and rates those it met. The runs launched at 23:03 the day before were stopped at 23:50 with nothing worth keeping, and the day-0 baseline with them; both restart under the new rules once the suite passes. The capability harness now freezes skills for every group (1273fca): it measures a resident as it stands, within one task nothing written there could be read back, and a group-specific switch would have confounded group D's change against the shared day-0 baseline.

The frontend direction was given after a sub-agent had already pushed the new minimal timeline page to the server as a release and extended the firewall for a reverse tunnel. Everything on the host was reverted the same hour: the site points again at the 13 October release, the firewall table is its 3 October version, nginx and the isolation check pass, and CornerHead's service was never touched. One thing could not be undone: the push deleted the older of the two retained releases of 13 October, as the deployer always does after a switch; the serving release was not affected and the pre-migration backup remains. The previous design's frontend (a static site: viewer plus a content-hashed JSON bundle published by `frontend.publish` and pushed by `frontend/deploy/push.sh`, with home, run dashboard, town map and replay, timeline, person, evaluation and comparison views) is being restored from commit e841d09 and rebuilt for the new world's data, with the side-by-side event timeline and the progress overview added in its own visual language. Its publishing model, a bundle behind the server's login with no live API from the compute host, is kept.

An audit of the judge is running on the pilot's journals: the 81 contradicted claims of group B's days 1–3 read one by one to separate real distortions from judge errors, before any distortion rate is interpreted.

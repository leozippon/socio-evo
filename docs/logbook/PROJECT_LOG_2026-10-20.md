## Streamed decisions follow visible changes

Realtime decisions now retain received reasoning and answer drafts when a relevant visible event interrupts generation, then continue with the latest situation. The shared clock keeps advancing; unrelated changes and clock ticks alone do not restart a request. Only the accepted final decision commits its decision memory, notes and action, so an unfinished conversation response need not be spoken after a participant leaves. Frequent relevant events can delay that final decision. The community realtime example enables and explicitly preserves thinking; the detailed behavior is documented in [Real-time scheduling](../realtime-scheduling.md).

A bounded Zenith probe used three real gateway requests, each with at most 512 output tokens, while the model and gateway remained running. The stream exposes reasoning as `delta.reasoning`; the first probe expected `reasoning_content` and completed without capturing it before the probe itself failed. The corrected probe saved 12 reasoning chunks (59 characters), with empty answer content, then closed the stream. The running-request gauge was one before close and zero after one second; the abort counter did not increase, so this is evidence of released request load, not independent proof of GPU cancellation. A continuation carrying the partial assistant `reasoning_content` accepted a participant's departure and completed with `wait` and a null target. This verifies request compatibility and valid final JSON, not causal reliance on the saved reasoning or server-constrained schema output. Probe script, full private evidence and a reasoning-free summary are in `/private/tmp/zenith-stream-probe-20261020/`.

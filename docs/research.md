# Shared research pilot

This independent checkout is based on leozippon/socio-evo, branch `redesign-event-runtime`, commit `8cca4f9de2a6d54e8f7ef18f31be46295fe9c4f4`. It contains none of our later town modifications. Existing deployments and experiment records are untouched. The independent Zenith deployment is described below.

`experiments/configs/research.yaml` overlays the original town with a 14-day research pilot. The eight original residents and their backgrounds, private memories and skills, conversations, shops, hospital, body, sleep and clock remain. Client work is paused; no SWE-bench dataset, images or grading is loaded. The Office and original occupations still exist. All residents receive the same commission and an external one-off $420 living allowance, independent of their participation. This covers fourteen days of the original maximum $30 daily basic rent and food; it does not cover unlimited purchases or price changes. The usual shops, rent, taxes and mayor salary continue.

There is no prescribed topic, research leader, division of work, timetable, contribution score or automatic scientific verdict. Residents organize through existing speech, announcements and phone messages (when they own phones). Everyone awake and well enough to work may use the Office's research tools. Research counts as ordinary work, including energy use. Leaving the Office stops research work; other occupations retain their usual duties at their own workplaces.

The shared work lives under `<run>/research/files`, with `paper.md` the agreed paper entry point. Only the brief and facilities explanation exist initially. Each file mutation or command records its author, time, arguments, result and Git revision. Writes and commands carry the last read revision and run serially. File creation and editing reject a stale revision only when the target file changed; unrelated files and evidence records do not block them. Commands can affect arbitrary files, so they check the shared files tree, while ignoring changes confined to evidence records. Unknown revisions are rejected. This protects shared edits without assigning roles. Residents can inspect records but cannot rewrite the captured evidence. Claims and interpretations in the paper remain the residents' responsibility.

Commands run in short-lived CPU containers using the supplied Dockerfile. Only the shared files are writable; recorded evidence is mounted read-only. Personal memories, simulation state and Docker sockets are not mounted. There is no network or GPU access inside commands. Python and common numerical/scientific libraries are provided. Each command has 2 CPU cores, 2 GiB memory and a 120-second limit; a project can consist of many commands, saving intermediate results. No research container is created before a command is invoked.

`search_literature` retrieves up to eight Crossref bibliographic matches, not general web search or guaranteed full-text access. `read_source` retrieves public HTML, plain text or PDF up to 8 MiB, with source URLs and text captured as evidence. Paywalls, scanned PDFs, inaccessible sites and failed requests remain failures. CSV or JSON source text can be processed from its recorded response in Python. Private network targets are refused. No paid API or browsing account is supplied.

World checkpoints store the shared repository revision alongside the original resident snapshots. Resume restores shared files and evidence to that revision, preserving later versions in Git history, and neither repeats the initial commission nor pays the allowance again. There is no automatic early termination upon writing a paper. At the configured final checkpoint, its current paper, supporting files and records remain available for inspection.

## Inspecting prompts

Run `python -m ops.research.preview --output docs/research-preview` to regenerate the initial system prompts, common commission, research help and tool schemas. This constructs temporary state only; it makes no model, network or Docker requests, and does not run the town clock. The exported files are review artifacts, not an experiment run.

## Deployment

Use Python 3.11 or newer and install `pip install -e '.[research,dev]'`. The original model client uses the modern OpenAI SDK and `httpx2`. Build the standalone CPU image with `docker build -t socio-evo-research:local -f ops/research/Dockerfile .` on the future execution host. Configure `VLLM_BASE_URL` and `VLLM_API_KEY` for its OpenAI-compatible serving endpoint; the base configuration retains the original model and two-replica settings. The `research-zenith.yaml` overlay selects the available official FP8 model with one TP=2 replica and eight concurrent resident requests.

The research directory must reside on the Docker host. This minimal version assumes local Docker on that host; it does not support a remote Docker daemon whose host cannot see the run path. Research has no SWE-bench scripted dry-run; use the preview and research tests for offline verification. The independent research viewer runs with `python -m frontend.research_server --runs-root RUNS --site SITE --port 8918`. It provides the paper, shared files, immutable command/source records and resident activity, and links to the original town and personal trace views. It reads the run without changing it.

The deployment root is `/project_c20250210/260903018/socio-evo-research/research-20261112-r1` on the two-A100 development machine (SSH port 2936). Code, Python environment, CPU image, model key, logs and run directory are independent of earlier deployments. `ops/research/model_service.py --root ROOT` starts the model on localhost:8040, verifies tool calling, and stops its own model after an existing experiment finishes or stops. Its private FlashInfer overlay fixes a Python 3.11 annotation incompatibility without modifying the shared serving environment. All residents share this single TP=2 service; reasoning effort and town timing retain the upstream settings. The viewer is reached through SSH forwarding at `http://127.0.0.1:8918/`; the earlier website on 8912 is unchanged.

The CPU runner uses host user-namespace mapping to match ownership of its two explicit bind mounts on this Docker daemon. It retains the read-only root, read-only evidence, absent network, dropped capabilities and CPU/memory/time limits. A real preflight verified scientific imports, persistent results, refused evidence writes and timeout cleanup before launch.

For a live code update, `python -m ops.research.checkpoint_update --root ROOT --code PREPARED_CHECKOUT --run RUN` performs a read-only preflight. Add `--watch` to wait for the next completed daily checkpoint, briefly hold the model supervisor, stop only this town, back up its complete run directory and resume with the prepared code. Status and the source revision are recorded in `checkpoint-update.json`. This preserves the completed day; any events after that checkpoint and before the stop remain in the backup and original world log, but are excluded by the normal resume semantics. It does not inject code into a live resident process.

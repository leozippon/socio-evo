# Version-aware research browser

The Office browser serves actual arXiv paper versions and GitHub repository contents selected at the simulation's current instant. It provides search, linked document and repository navigation, paginated reading, and byte-preserving downloads. It does not generate substitute pages or treat present-day snippets as historical evidence. Only arXiv and GitHub are supported.

## Interface and isolation

`world.research_browser.BrowserGateway(cache_dir)` exposes synchronous `search(provider, query, as_of, page=1)`, `open(url, as_of, offset=1, limit=120)`, and `download(url, as_of, destination)` methods. The world supplies the timezone-aware cutoff; residents cannot choose it. The gateway converts it to UTC and rejects a cutoff in the real-world future. The caller must validate the destination inside the shared research workspace and record the complete returned result.

Search pages contain up to five provider candidates; a page can contain fewer eligible results and still have a next page. Open results contain numbered text, fixed-version links, and `next_offset`. Long physical lines are divided into 240-character reading lines. Links are paginated with the same offset/limit and provide `next_links_offset` separately. Reopening the returned URL with the next offset continues reading. A directory links to its files and subdirectories; an arXiv abstract links to its exact-version PDF and source archive. PDFs are extracted as text; source archives and binary files should be downloaded.

The host-only cache stores fetched bytes by SHA-256 and URL metadata containing the retrieval time and content type. Results include the version, timestamp basis, cutoff, retrieval time and hashes. Downloads allow up to 256 MiB, preserve the fetched bytes, and do not unpack archives. Ordinary metadata and code reads are limited to 8 MiB. Cached content is checked against the supplied cutoff on every operation, including after a simulation restore. Mutable search responses and arXiv history are fetched again if the simulation advances beyond their real retrieval time; exact-version artifacts remain reusable. The cache is deliberately outside resident mounts; it may contain discovery metadata mentioning later versions that must never be shown directly to residents.

The research container must have direct network access disabled in this mode. Existing live `curl`, Tavily, Semantic Scholar and unrestricted `read_source` routes must not remain alternate routes to the present-day internet. Approved downloads enter the shared workspace through the gateway. An HTTP proxy environment variable alone would not provide this isolation.

## Source behavior

For arXiv, the official advanced HTML search discovers candidate identifiers within a submission-date range. Current search titles and abstracts are discarded. Plain keywords use the website's all-fields search; a single `ti:`, `au:` or `abs:` field maps to title, author or abstract. Complex API query syntax is rejected instead of silently changing its meaning. The website returns 50 candidates per page, which the gateway caches and slices into five-candidate tool pages. A form-only response or unrecognized block page is an error, not an empty search. [arXiv advanced search](https://arxiv.org/search/advanced)

The gateway reads submission history internally, selects the latest eligible version (or validates an explicit version), and opens that exact `vN` abstract page. It reads the visible title, authors and abstract only after checking both the explicit version label and the actual versioned PDF link. Citation metadata alone is insufficient: `citation_pdf_url` can omit `vN` even on an old version's page. PDF and source links are constructed with the validated version. Later version history is not returned. Failed history parsing or a page for the wrong version is an explicit error, with no fallback to latest. The separate export API is not required by this route. The API manual remains a useful reference for version-qualified identifiers and submission timestamp semantics. [arXiv API manual](https://info.arxiv.org/help/api/user-manual.html)

For GitHub, repository search explicitly requests public repositories and discards non-public results, without exposing current stars, forks, descriptions or citation-like popularity signals. Before any repository content is served, a fresh repository-metadata request must confirm that it is currently public and was created by the cutoff. This check is required even for cached content and even when the optional token can access private repositories; failed or unavailable visibility checks do not reuse an earlier authorization. Repository roots and named refs then resolve through commits at or before the cutoff; explicitly supplied full SHAs are checked directly. README, directories, files and repository archives are fetched using that full SHA. Navigation emits pinned links. Branch names containing slashes should be resolved externally to a full SHA before using a tree/blob URL; ambiguous ref/path splitting is not guessed. [GitHub search API](https://docs.github.com/en/rest/search/search), [commit API](https://docs.github.com/en/rest/commits/commits), [contents and archive API](https://docs.github.com/en/rest/repos/contents)

arXiv requests are spaced by at least three seconds within the process. HTTP 429 and transient 5xx responses receive at most two retries with bounded waiting; other HTTP errors fail explicitly. A host-side `GITHUB_TOKEN` is optional, is sent only to `api.github.com`, and is never included in tool arguments, results or cache metadata. Redirects remain restricted to the supported HTTPS provider hosts. The real provider probes in deployment preflight are separate from local fixture tests; passing those tests alone does not establish provider availability.

## What this cannot prove

This is a version-aware source browser, not a certified reconstruction of the historical public web. Every document reports `availability_verified: false` and its timestamp basis:

- An arXiv submission timestamp does not prove that the work was publicly announced by that instant. Moderation, announcement schedules and deferred mailings can delay publication. This implementation does not infer an announcement time from the normal schedule. [arXiv availability and announcement process](https://info.arxiv.org/help/availability.html)
- Git author and committer dates can be supplied by the author. A pinned SHA gives reproducible contents but does not prove when a repository or commit became publicly accessible. The current default branch, repository name, visibility and history reachable from a ref may differ from their historical states. [Git commit dates](https://git-scm.com/docs/git-commit)
- Candidate discovery uses current provider indexes. Filtering dates and replacing snippets cannot reconstruct historical coverage, ranking, deleted repositories, or papers whose earlier text matched a query but whose latest text no longer matches. A current index can also match a term introduced only in a later version; the historical snippet must be assessed by the resident. Search results are leads, not proof of a historically exhaustive search.
- A cache freezes observations when they are first retrieved, not when they were originally published. A model may already know later facts from training, and preinstalled software and model weights have their own provenance. Tool isolation does not erase that knowledge.

These boundaries must accompany experimental conclusions. A strict claim that all information was publicly available before the cutoff requires independently timestamped captures or an audited release corpus, beyond the live provider interfaces implemented here.

## Relevant archive projects

[Webrecorder pywb](https://github.com/webrecorder/pywb) is an open-source WARC capture and replay system with URL rewriting and Memento support. It is a useful future replay backend, but capture selection and every dependent resource would need to be restricted to timestamps at or before the cutoff, and live fallback disabled. [Browsertrix Crawler](https://github.com/webrecorder/browsertrix-crawler) can prepare browser-based WARC/WACZ captures; a capture made today does not establish what a site served months ago.

[Software Heritage snapshots](https://docs.softwareheritage.org/devel/swh-web/uri-scheme-api-snapshot.html) and [origin visit records](https://docs.softwareheritage.org/devel/journal.html) can provide independent observations of repository state. They are not integrated here. A visit before the cutoff can support a historical-availability claim for the captured snapshot; choosing the nearest visit without checking its direction could select a later observation. These sources are preferable to pretending a Git committer date certifies public release.

For a future graphical browser, [Playwright network routing](https://playwright.dev/python/docs/network) can drive archived pages and expose interactions. Its documentation notes that service workers can bypass normal route visibility; browser request interception would supplement, rather than replace, network isolation. The current resident tool result is text, so the minimal implementation uses real linked text pages and downloadable artifacts instead of adding a separate screenshot or multimodal interface.
